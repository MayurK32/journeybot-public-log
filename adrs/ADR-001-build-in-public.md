# ADR-001: Build JourneyBot in Public

**Status:** Accepted

**Date:** 2026-06-25

## Context

JourneyBot is a commercial side project that I plan to grow over time. Alongside building the product, I also want to become a better software engineer by improving my understanding of software architecture, system design, distributed systems, and technical decision making.

Instead of keeping the journey private, I decided to document the engineering process publicly.

## Decision

JourneyBot will be built in public.

The implementation and source code will remain private, while architecture decisions, trade-offs, lessons learned, and progress updates will be shared publicly.

## Rationale

- Creates accountability and encourages consistent progress.
- Documents the reasoning behind technical decisions.
- Improves technical writing and communication skills.
- Builds a public engineering portfolio.
- Allows others to learn from real engineering decisions.

## Alternatives Considered

### Build the project privately

This would allow unrestricted experimentation but would miss the opportunity to document decisions and receive feedback.

## Consequences

### Positive

- Engineering decisions are documented.
- Progress becomes measurable over time.
- The repository becomes a public engineering journal.

### Negative

- Documentation requires additional effort.
- Technical decisions become open to public discussion.

## Future Considerations

Commercially sensitive implementation details and source code will continue to remain private while architecture decisions and engineering learnings remain public.
